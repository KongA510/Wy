# 关于生命周期
<p class="Content_body">生命周期是条目实例在其存在期间所经历的一系列状态（即阶段或关口）。大多数业务流程会定义高层级阶段，以跟踪对象在生命周期中的进度。以下是一个生命周期的示例：</p>

<p class="Content_body">生命周期由<span style="font-weight: bold;">状态</span>和<span style="font-weight: bold;">转换</span>组成。状态本质上是一系列动作和步骤，而转换则是不同状态之间的路径。让我们一起了解这个周期，以获得一些基本的认识。</p>

<p class="Content_body">当创建一个名为 PartsVendor1 的供应商 ItemType（物料类型）实例时，它会立即被置于"初始"状态。通常，为了获得"已批准"供应商的资格，供应商必须满足某些公司特定的标准，或通过特定的流程。当这些标准得到满足后，组件工程身份组的成员可以将 PartsVendor1 晋级到"已批准"状态。如果 PartsVendor1 满足更严格的标准（通常涉及更紧凑的交货期或批量折扣），则组件工程身份组的成员可以将该供应商晋级到"首选"状态。当然，如果供应商在某些方面未达标（同样根据公司设定的标准），则可以将该供应商转换到"停用"状态。通常，在每个状态内部，都有一系列需要由指定身份组执行的步骤或动作。这些通常会在工作流映射中进行描述和分配，并且可以在条目进入特定生命周期状态时自动激活。</p>
<p class="Content_body">作为一个非常强大的工具，可以在条目状态变更时触发各种设置的启用和停用。例如，一个设置可能是：当采购身份组的成员为特定零件选择供应商时，只有处于"首选"状态的供应商才会被用于填充可用供应商列表。另一个功能是，当条目进入任何生命周期状态时，可以设置电子邮件通知，自动告知选定的身份组由于此状态变更而必须执行的动作项。</p>
