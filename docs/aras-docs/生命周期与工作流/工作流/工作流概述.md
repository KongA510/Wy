# 关于工作流
<p class="Content_body">工作流是一系列已定义的活动序列，用于表示业务流程，例如 ECN 审批流程。工作流通常包含分支和并行活动，并嵌入过程规则。在 Innovator 中，<span style="font-weight: bold;">工作流映射（Workflow Map）</span>代表可多次运行的业务流程模板。工作流映射的实例称为<a id="Process" name="Process"></a><span style="font-weight: bold;">工作流流程（Workflow Process）</span>。工作流流程跟踪实际参与者、流程中的条目实例，以及所做出的任何决策。工作流在确保业务流程的所有步骤按正确顺序和可重复方式完成方面具有重要价值。</p>
<p class="Content_body">让我们来看一个工作流映射，并讨论其不同的组成部分。以下截图展示了一个分为三个部分的表单。顶部是图形化的工作流设计器，即图表区域，其中图表表示活动模板及连接它们的工作流映射路径。中间部分包含图表中所选条目的头部属性。在本例中，图表中未选择任何内容，因此显示的是工作流映射自身的头部属性。底部部分包含与图表中所选组件相关的选项卡。</p>

<p class="Content_body">如前所述，工作流映射由活动（Activity）和路径（Path）组成。每个活动代表一个必须执行的工作单元，包含任务列表、负责这些任务的身份组分配、任何附带通知，以及由活动跟踪和存储的任何变量（如活动所花费的小时数）。活动还具有决定其在工作流中行为的属性，包括是否需要用户交互、是否可以拒绝或委托、是否必须在遵循路径之前收到所有投票，以及是否所有输入路径必须在启动之前完成。路径同样具有决定其行为的属性，包括该路径是否为活动的"默认"退出路径，以及该路径是否"覆盖"所有其他投票。这些属性如何影响整体工作流将在后续详细讨论并通过示例展示。</p>
<p class="Content_body">当活动被激活时，已分配给该活动的身份组（即被分配人）会收到通知，该活动将出现在他们的收件箱（InBasket）中。被分配人随后打开所谓的活动完成工作表，该工作表引导他们完成需要执行的任务列表以及活动完成前需要进行的其他工作。此外，被分配人将有机会选择活动的退出路径，即投票。根据该投票结果，将选择下一个要激活的活动。</p>
